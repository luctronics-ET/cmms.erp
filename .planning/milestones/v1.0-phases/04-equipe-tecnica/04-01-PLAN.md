## Capacity formula (extracted verbatim from .docs_cmasm/referencias/cmasm13-govbr-v8_3.html, lines 889-903)

The legacy app computes capacity from CONFIG ONLY — it does **not** multiply by member count.
Members (`pessoas`) are a roster with an `ativo` flag; they never enter the capacity arithmetic.
This resolves the CONTEXT "Claude's Discretion" question: follow the legacy → capacity is
`num_equipes × Σ(turnos.horas) × len(dias_semana)`, members excluded.

Legacy JS (authoritative source of the numbers):

  horasPorDiaEquipe()  = Σ turnos[i].horas                    // soma das horas dos turnos
  hDiaEquipe           = horasPorDiaEquipe()                  // h/dia por equipe
  hDiaTotal            = hDiaEquipe × num_equipes             // h/dia total (todas as equipes)
  hSemana              = hDiaTotal × len(dias_semana)         // h/semana
  hMes                 = hSemana × 4.345                      // h/mês (aprox. semanas/mês)
  hAno                 = hSemana × 52                          // h/ano (52 semanas)

Legacy default config: num_equipes=1, dias_semana=[seg..sex] (5 dias), turnos=[{Manhã,2h},{Tarde,2h}].
→ hDiaEquipe=4, hDiaTotal=4, hSemana=20, hMes=86.9, hAno=1040.

The backend `_capacidade(config)` helper MUST reproduce these. Return keys (snake_case for the API):
`h_dia_equipe`, `h_dia_total`, `h_semana`, `h_mes`, `h_ano`. Round h_mes to a float; keep h_dia/h_semana/h_ano
as the exact arithmetic results (integers when inputs are integers) so the test can assert exact numbers.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | equipe_membros / equipe_config writes | high | mitigate | All writes go through parameterized SQL (aiosqlite ?-binding); no string interpolation of user input |
| T-04-02 | Spoofing | equipe endpoints | high | mitigate | _require_auth on every route; writes additionally reject role=visualizador (403) |
| T-04-03 | Information Disclosure | usuario_mat link | low | accept | Optional plain mat reference, no sensitive payload; no extra exposure beyond existing /api/usuarios |

| T-04-05 | Tampering | soft-delete bypass | medium | mitigate | No DELETE route — deactivation is ativo=0 only; test asserts row survives soft-delete |
